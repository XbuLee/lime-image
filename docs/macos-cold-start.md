# macOS 冷启动时未打开 Finder 选中的文件

## 原因

macOS 的 Finder / Dock 打开文件通过 AppDelegate 的文件打开回调传递，不依赖 Dart `main(args)`。

原实现有两个丢失路径：

1. `applicationDidFinishLaunching` 建立通道后立即 `flushPending()`，清空原生缓存。此时 Dart 的消息处理器或文件事件监听器可能尚未就绪。
2. `PlatformOps.initChannel()` 在启动最前面调用 `consumePendingFiles`，再把结果加入广播流。`ViewerPage.initState()` 要到配置、窗口初始化及 `runApp` 之后才监听；广播流不保留没有监听者时发送的事件。首次语言选择页也会延长这段时间。

因此，原生侧已经收到文件，并不意味着图片页面收到了文件。应用已运行时监听者存在，所以再次打开往往正常。

## 修复

- 原生层保留文件，直到 Dart 主动调用 `consumePendingFiles`，然后才启用后续推送。
- 待打开文件作为启动参数交给 `ViewerState.initialize`，优先于恢复上次图片。
- Dart 端缓存没有监听者时收到的事件，包括语言选择及初始化期间的请求。
- 初始化完成后统一处理后续文件请求，顺序打开，避免恢复上次图片与新请求互相覆盖。

## 验证状态

`test/platform_ops_test.dart` 覆盖监听前缓存、顺序交付、不重复交付，以及原生通道提前发送文件。两项测试已在独立临时测试工程中通过，静态分析通过。临时工程使用本项目的实际 `platform_ops.dart` 和测试文件。

本机 Flutter 3.44.0 / Dart 3.12.0 低于项目要求的 Dart 3.13.2，因此完整项目的依赖解析未通过，尚未完成 macOS 应用编译及 Finder 端到端验证。项目 SDK 要求未修改。

## 匹配 SDK 后的人工回归

1. 完全退出应用（确认进程结束），通过 Finder 的“打开方式”选择一张图片。应直接显示选中图片。
2. 开启“恢复上次图片”，退出后选择另一张图片冷启动。最终应显示本次选中的图片。
3. 应用运行时再打开另一张图片，确认切换正常。
4. 使用独立的测试配置，让应用显示首次语言选择页；从 Finder 打开图片，选择语言后应显示该图片。
5. 测试带中文和空格的路径，以及拖到 Dock 图标打开。

这些修改需要重新编译才会影响应用；已安装的官方版本未修改。
